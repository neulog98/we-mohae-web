# 우리뭐해 상세 스토리보드

## 1. 서비스 개요

`우리뭐해`는 두 사용자가 하나의 커플 공간을 공유하며 일정과 결혼 준비 예산을 관리하는 모바일 우선 웹/PWA이다. 사용자는 이메일/비밀번호로 로그인하고, 온보딩에서 `커플 모드` 또는 `예비부부 모드`를 선택해 개인 커플 공간을 만든다. 파트너는 초대코드를 입력해 같은 커플 공간에 합류한다.

모드별 기능 차이:

- 커플 모드: 홈, 캘린더, 설정을 사용한다. 일정 타입은 `couple`로 고정된다.
- 예비부부 모드: 홈, 캘린더, 예산관리, 설정을 사용한다. 캘린더는 `커플 일정`과 `결혼 준비 일정`을 분리하고, 예산 항목은 결혼 준비 일정과 연결할 수 있다.

저장 구조:

- 사용자: `users/{uid}`
- 커플 공간: `couples/{coupleId}`
- 일정: `couples/{coupleId}/schedules/{scheduleId}`
- 예산: `couples/{coupleId}/budgets/{budgetId}`
- 푸시 토큰: `couples/{coupleId}/fcmTokens/{token}`
- 초대코드 인덱스: `inviteCodes/{inviteCode}`

## 2. 공통 인증과 라우팅

### 2.1 앱 최초 진입

진입점 `/`:

1. 화면 중앙에 기본 로딩 상태를 표시한다.
2. 클라이언트에서 즉시 `/home`으로 `replace` 이동한다.
3. `/home` 진입 후 보호 라우트 게이트가 로그인/온보딩 상태를 판정한다.

### 2.2 보호 화면 공통 AuthGate

적용 화면:

- `/onboarding`
- `/invite`
- `/home`
- `/calendar`
- `/budget`
- `/settings`

상태별 플로우:

| 상태 | 조건 | 화면/전이 |
| --- | --- | --- |
| 인증 확인 중 | Firebase Auth 또는 프로필 구독 대기 | 중앙 로딩 카드 표시 |
| 비로그인 | `user == null` | `/login`으로 replace |
| 로그인, 프로필 없음/오류 | `profile == null` 또는 오류 | 오류 카드, Firestore 안내 문구, `다시 시도`, `로그아웃` 버튼 표시 |
| 로그인, 온보딩 미완료 | 보호 화면에서 `mode` 또는 `coupleId` 없음 | `/onboarding`으로 replace |
| 로그인, 온보딩 완료 | `mode`와 `coupleId` 모두 존재 | 요청 화면 렌더링 |
| 온보딩 화면에 이미 완료 사용자가 접근 | `/onboarding`, `requireOnboarding=false`, 온보딩 완료 | `/home`으로 replace |

데이터 정합성:

- 로그인 후 `ensureUserProfile`이 `users/{uid}` 문서를 보장한다.
- 신규 프로필은 `email`, `displayName`, `coupleId:null`, `mode:null`, 생성/수정 시각을 가진다.
- 보호 화면에서는 `NativePushTokenSync`가 함께 렌더링되어 Android 앱 환경이면 현재 토큰을 커플 공간에 동기화한다.

### 2.3 공통 레이아웃 AppShell

노출 요소:

- 상단 헤더: 현재 모드 라벨과 화면 제목
- 하단 탭: 홈, 캘린더, 설정
- 예비부부 모드에서만 하단 탭에 `예산관리` 추가

전이 조건:

- 하단 탭 클릭 시 해당 라우트로 이동한다.
- 커플 모드에서는 예산 탭이 렌더링되지 않는다.
- `/budget` 직접 접근은 화면에서 빈 상태를 잠시 표시한 뒤 `/home`으로 replace한다.

## 3. 로그인/회원가입 `/login`

### 3.1 기본 화면

첫 화면 구성:

- 앱 아이콘과 서비스명
- 설명 문구
- 이메일 입력
- 비밀번호 입력
- 로그인 버튼
- `비밀번호를 잊으셨나요?` 버튼
- `처음이에요. 계정 만들기` 전환 버튼

초기 상태:

- `isSignUp=false`
- `email=""`
- `password=""`
- `displayName=""`
- `loading=false`
- `authError=null`
- `passwordResetOpen=false`

### 3.2 로그인 제출

사용자 액션:

1. 이메일과 비밀번호 입력
2. `로그인` 클릭

검증:

- 이메일 input은 `type=email`, `required`이다.
- 비밀번호 input은 `required`, `minLength=6`이다.
- 브라우저 기본 검증을 통과해야 제출된다.

전이:

1. `loading=true`, 기존 오류 제거
2. Firebase `signInWithEmailAndPassword`
3. 성공 시 `ensureUserProfile`
4. 프로필에 `mode`와 `coupleId`가 있으면 `/home`
5. 없으면 `/onboarding`
6. 성공 토스트: `로그인됐어요.`

오류:

- 잘못된 자격 증명: `이메일/패스워드가 다릅니다. 확인 후, 다시 시도해주세요.`
- 올바르지 않은 이메일: `올바른 이메일 주소를 입력해주세요.`
- 과도한 시도: `로그인 시도가 너무 많아요. 잠시 후 다시 시도해주세요.`
- 네트워크 실패: `네트워크 연결을 확인한 후 다시 시도해주세요.`
- Firebase 환경변수 없음: 설정값 입력 안내 메시지
- 오류는 화면 상단 오류 카드와 토스트로 동시에 노출된다.

### 3.3 회원가입 전환과 제출

전환 액션:

- `처음이에요. 계정 만들기` 클릭 시 `isSignUp=true`
- 버튼 문구는 `이미 계정이 있어요`로 변경
- `이름` 입력 필드가 추가된다.

회원가입 제출:

1. 이메일, 비밀번호, 선택적 이름 입력
2. `회원가입` 클릭
3. `createUserWithEmailAndPassword`
4. Firebase Auth displayName 업데이트
5. 프로필 생성
6. 온보딩 미완료 상태이므로 `/onboarding`으로 이동

검증/정합성:

- 이름이 비어 있으면 이메일의 `@` 앞부분을 displayName으로 사용한다.
- 이미 가입된 이메일은 로그인 유도 오류 메시지를 표시한다.
- 약한 비밀번호는 `비밀번호는 6자 이상 입력해주세요.`를 표시한다.

### 3.4 비밀번호 재설정

진입:

- 로그인 모드에서 `비밀번호를 잊으셨나요?` 클릭
- 전체 화면 다이얼로그로 `비밀번호 재설정` 표시
- 초기 이메일은 로그인 화면 이메일 값을 이어받는다.

검증:

- 이메일 input은 `required`, `type=email`

제출:

1. `재설정 메일 받기` 클릭
2. `sending=true`, 버튼 문구 `발송 중...`
3. Firebase `sendPasswordResetEmail`
4. 성공 시 다이얼로그 닫힘
5. 로그인 화면 이메일을 발송 이메일로 갱신
6. 토스트: `가입된 계정이라면 비밀번호 재설정 메일을 보냈어요.`

보안성:

- 계정이 존재하지 않는 이메일이어도 성공처럼 처리한다.
- 계정 존재 여부를 외부에 노출하지 않는다.

닫기:

- 상단 X, 하단 취소, Escape 키로 닫는다.

## 4. 온보딩 `/onboarding`

### 4.1 진입 조건

진입 가능 상태:

- 로그인되어 있으나 `profile.mode` 또는 `profile.coupleId`가 없는 사용자

자동 이탈:

- 이미 온보딩 완료 사용자가 접근하면 `/home`으로 이동한다.

### 4.2 모드 선택

화면 구성:

- 제목: `어떤 일정부터 함께 정리할까요?`
- 커플 모드 카드: 데이트, 약속, 기념일 중심
- 예비부부 모드 카드: 결혼 준비 일정과 예산 관리

액션별 전이:

| 액션 | 데이터 처리 | 다음 화면 |
| --- | --- | --- |
| 커플 모드 클릭 | `couples` 문서 생성, `mode="couple"`, `memberIds=[uid]`, 초대코드 생성, 사용자 프로필 갱신 | `/invite` |
| 예비부부 모드 클릭 | `couples` 문서 생성, `mode="wedding"`, `memberIds=[uid]`, 초대코드 생성, 사용자 프로필 갱신 | `/invite` |

데이터 정합성:

- 커플 문서와 초대코드 문서, 사용자 프로필 갱신은 batch로 커밋된다.
- 초대코드는 8자리이며 혼동 방지를 위해 `I`, `O`, `1`, `0` 등은 제외된 문자셋을 사용한다.
- 초대코드 충돌 재시도는 현재 구현되어 있지 않으므로 충돌 가능성은 낮지만 후속 보완 대상이다.

오류:

- 커플 생성 실패 시 토스트: `온보딩에 실패했어요.`

## 5. 초대 연결 `/invite`

### 5.1 상태 판정

구독 데이터:

- `couples/{coupleId}` 실시간 구독
- `memberIds`에서 본인 외 uid를 찾아 파트너 `users/{partnerId}` 실시간 구독

연결 상태:

- `connected=true`: 커플 문서가 있고 `memberIds.length === 2`
- `connected=false`: 본인만 있는 커플 공간

### 5.2 미연결 상태 화면

노출:

- 내 초대코드
- 복사 버튼
- 재생성 버튼
- 받은 초대코드 입력 폼
- 연결 상태 카드: `파트너를 기다리는 중이에요`

초대코드 표시:

- 커플 데이터 로드 전에는 `--------`
- 커플 데이터 로드 후 실제 `inviteCode` 표시

복사 액션:

1. 복사 버튼 클릭
2. Clipboard API 또는 fallback 실행
3. 성공 토스트: `초대코드를 복사했어요.`
4. 실패 토스트: `초대코드 복사에 실패했어요.`

재생성 액션:

1. 재생성 버튼 클릭
2. 새 초대코드 생성
3. 커플 문서의 `inviteCode` 갱신
4. 새 `inviteCodes/{code}` 생성
5. 기존 초대코드 인덱스 삭제
6. 토스트: `새 초대코드 {code}를 만들었어요.`

초대코드 입력 액션:

1. 받은 초대코드 입력
2. `연결하기` 클릭
3. 입력값은 trim, uppercase, 공백 제거로 정규화
4. `inviteCodes/{code}` 조회
5. 커플 문서 `memberIds`에 현재 uid 추가
6. 커플 문서 재조회 후 멤버 수 검증
7. 사용자 프로필의 `coupleId`, `mode`를 상대 커플 공간 값으로 갱신
8. 성공 토스트 후 `/home`

오류/검증:

- 코드가 없으면 `유효한 초대코드를 찾지 못했어요.`
- 멤버가 이미 2명을 초과하면 `이미 두 명이 연결된 초대코드예요.`
- Firestore 규칙에서도 커플 멤버 수는 최대 2명으로 제한된다.
- 입력 필드는 HTML `required`가 없으므로 빈 문자열 제출 시 서비스 조회 오류로 처리된다.

### 5.3 연결 완료 상태 화면

노출:

- 초대코드 생성/입력 폼 숨김
- 연결 카드: `연결 완료`
- 파트너 프로필 로드 완료 시 `{displayName}님과 함께 쓰고 있어요.`
- 파트너 프로필 로드 전 또는 없음: 상대방 입력 대기 문구가 표시될 수 있다.

## 6. 홈 `/home`

### 6.1 공통 홈

데이터:

- 현재 날짜
- 파트너 연결 상태
- 다가오는 일정 5개

화면 구성:

- 오늘 날짜: `M월 d일 EEEE`
- 헤드라인: `우리 이번 주 뭐해?`
- 연결 메시지:
  - 파트너 있음: `{파트너명}님과 함께 일정을 보고 있어요.`
  - 미연결: `초대코드로 파트너를 연결해보세요.`
- `일정 추가하기` 버튼: `/calendar` 이동
- 다가오는 일정 섹션과 `전체보기` 링크

로딩/빈 상태:

- 일정 구독 중: `다가오는 일정을 불러오는 중이에요`
- 일정 없음: `아직 등록된 일정이 없어요`

일정 리스트:

- 시작일이 현재 시각 이상인 일정만 표시
- `startAt` 오름차순
- 최대 5개
- 각 항목은 제목, D-Day, 일시, 카테고리를 표시

구현상 주의:

- 홈의 다가오는 일정은 모드/타입 필터를 하지 않고 커플 공간의 모든 예정 일정을 가져온다. 예비부부 모드에서는 커플 일정과 결혼 준비 일정이 함께 섞일 수 있다.

### 6.2 예비부부 모드 홈 확장

추가 노출:

- 결혼 준비 예산 요약
- 다가오는 결제일 3개

예산 요약:

- 총 예상 예산
- 총 계약금
- 총 결제금액
- 남은 결제금액

다가오는 결제일:

- 예산 항목에서 계약금일, 잔금일, 기존 호환용 `paymentDate` 중 오늘 이후 가장 가까운 날짜를 계산
- 가까운 결제일 순 정렬 후 3개 표시
- 결제일이 없으면 `예정된 결제일이 없어요`

데이터 정합성:

- 남은 결제금액은 `max(총 예상 예산 - 총 결제금액, 0)`이다.
- 항목 카드의 금액은 현재까지 결제 금액(`paidAmount`)을 표시한다.

## 7. 캘린더 `/calendar`

### 7.1 화면 초기 상태

상태:

- `monthDate = 오늘`
- `selectedDate = 오늘`
- `editing = null`
- `deleteTarget = null`
- `scheduleType = "couple"`

데이터:

- 선택 월의 시작일~말일 범위에서 `startAt` 기준 일정 구독
- `startAt` 오름차순 정렬

로딩/빈 상태:

- 월간 일정 로딩: `월간 일정을 불러오는 중이에요`
- 선택 날짜에 표시할 일정 없음: `두 분의 첫 일정을 추가해보세요`

### 7.2 모드별 캘린더 분기

커플 모드:

- 일정 타입은 항상 `couple`
- 타입 전환 세그먼트 미노출
- 카테고리: 데이트, 기념일, 약속, 여행, 기타

예비부부 모드:

- 상단 세그먼트 표시
- `커플 일정` 선택 시 `type == "couple"` 일정만 표시
- `결혼 준비 일정` 선택 시 `type == "wedding"` 일정만 표시
- 카테고리는 타입에 따라 달라진다.
- 타입 전환 시 `editing`은 초기화되어 수정 중인 폼이 닫힌다.

### 7.3 월간 달력 조작

이전/다음 달:

- 이전 달 버튼 클릭: `monthDate`를 한 달 전으로 변경
- 다음 달 버튼 클릭: `monthDate`를 한 달 후로 변경
- 변경 즉시 해당 월 범위로 Firestore 구독이 갱신된다.

날짜 선택:

- 날짜 셀 클릭 시 `selectedDate` 변경
- 선택 날짜와 같은 날짜(`isSameDay`)의 일정만 하단 리스트에 표시
- 일정이 있는 날짜에는 점 표시

데이터 표시 제한:

- 월 범위 쿼리는 일정 시작일이 해당 월 안에 있는 일정만 포함한다.
- 종료일이 다음 달에 걸치는 일정도 시작일이 현재 월 밖이면 현재 월에는 표시되지 않는다.

### 7.4 일정 추가

폼 필드:

- 일정 제목: 필수
- 설명: 선택
- 시작일: `datetime-local`
- 종료일: `datetime-local`, 선택
- 종일 일정: 체크박스
- 카테고리: 현재 일정 타입의 카테고리 목록
- 알림: 하루 전/당일 오전 9시 알림 활성화 체크

제출 전 상태:

- 신규 작성 폼은 선택 날짜를 시작일 초기값으로 사용한다.
- 신규 저장 후 제목과 설명은 초기화된다.

제출 플로우:

1. `커플 일정 추가` 또는 `결혼 준비 일정 추가` 클릭
2. 브라우저가 제목 필수 여부 검증
3. `saving=true`, 버튼 비활성화
4. `addSchedule(coupleId, uid, activeScheduleType, input)`
5. Firestore 문서 생성
6. 생성된 문서 id를 `scheduleId`로 업데이트
7. 성공 토스트: `일정을 추가했어요.`
8. 실시간 구독에 의해 달력과 리스트 갱신

데이터 정합성:

- `createdBy`, `updatedBy`는 현재 uid
- `createdAt`, `updatedAt`은 서버 시각
- `startAt`, `endAt`은 Firestore Timestamp
- `type`은 커플 모드에서는 `couple`, 예비부부 모드에서는 선택된 세그먼트 값
- `reminderMinutesBefore`는 현재 항상 `null`이며 실제 알림 worker는 `reminderEnabled`를 사용한다.

구현상 검증 주의:

- 시작일 input에 `required`가 없다. 비정상적으로 비어 있으면 `new Date("")`가 Invalid Date가 될 수 있다.
- 종료일이 시작일보다 빠른 경우를 UI에서 막지 않는다.
- 제목은 브라우저 필수 검증만 사용하며 trim 검증은 없다.

### 7.5 일정 수정

진입:

- 일정 카드의 수정 버튼 클릭
- `editing`에 해당 일정 저장
- 폼 제목이 `일정 수정`으로 변경
- 폼 필드는 기존 일정 값으로 초기화
- 수정 중인 일정의 `type`을 active type으로 사용한다.

수정 제출:

1. 필드 수정
2. `일정 수정` 클릭
3. `updateSchedule(coupleId, scheduleId, uid, input)`
4. `updatedBy`, `updatedAt` 갱신
5. 성공 시 `editing=null`
6. 토스트: `일정을 수정했어요.`

취소:

- 수정 모드에서 `취소` 버튼 클릭 시 `editing=null`
- 신규 폼 상태로 돌아간다.

### 7.6 일정 삭제

진입:

- 일정 카드의 삭제 버튼 클릭
- ConfirmDialog 표시

다이얼로그:

- 제목: `일정을 삭제할까요?`
- 설명: `삭제한 일정은 바로 복구할 수 없어요.`
- 취소/닫기: 다이얼로그만 닫음
- 삭제 확인: 문서 삭제

삭제 전이:

1. `deleteSchedule(coupleId, scheduleId)`
2. 성공 시 `deleteTarget=null`
3. 토스트: `일정을 삭제했어요.`
4. 실시간 구독에서 리스트 제거

권한:

- `schedules`는 커플 멤버만 읽기/생성/수정/삭제 가능하다.

- 정렬 선택

필터:

- 전체

- 결제일 임박 순

로딩/빈 상태:

- 구독 중: `예산 항목을 불러오는 중이에요`
- 필터 결과 없음 또는 항목 없음: `결혼 준비, 하나씩 정리해볼까요?`

### 8.3 예산 항목 리스트

표시 항목:

- 제목
- 카테고리 및 세부 카테고리
- 계약금 결제일
- 잔금 결제일
- 다음 결제일
- 예상 예산
- 현재까지 결제 금액
- 수정/삭제 버튼

날짜 표시:

- 계약금일이 없으면 `미정`
- 잔금일은 `balancePaymentDate`가 있으면 우선 사용, 없으면 기존 호환용 `paymentDate` 사용
- 다음 결제일은 계약금일, 잔금일, `paymentDate` 중 오늘 이후 가장 빠른 날짜

정렬 정합성:

- 결제일 임박 순: 다음 결제일이 있는 항목을 날짜 오름차순으로 먼저 표시하고, 결제일 없는 항목은 뒤로 보낸다.
- 최근 추가 순: `createdAt` 내림차순

### 8.4 예산 항목 추가/수정 폼

진입:

- 추가: `예산 항목 추가` 클릭, `editing=null`, 전체 화면 다이얼로그
- 수정: 항목 카드의 수정 클릭, 기존 값으로 폼 초기화

섹션과 필드:

기본 정보:

- 항목명: 필수
- 카테고리: 예산 카테고리 중 선택
- 세부 카테고리: 자유 입력
- 세부 카테고리 추천 칩: 카테고리별 추천값 클릭 시 입력값으로 설정

금액 정보:

- 예상 예산
- 계약금
- 현재까지 결제 금액
- 남은 예상 금액 또는 예산 초과 금액

결제 정보:

- 결제자: 신랑, 신부, 공동
- 계약금 결제일
- 잔금 결제일
- 관련 결혼 준비 일정

메모:

- 업체 연락처, 결제 조건 등 자유 입력

폼 하단:

- 취소
- 추가 시 `예산 항목 저장`
- 수정 시 `수정 저장`
- 저장 중에는 `저장 중...`으로 변경하고 버튼 비활성화

### 8.5 예산 폼 검증과 정합성

HTML/UI 검증:

- 항목명은 `required`
- 금액 필드는 숫자 키패드 유도(`inputMode=numeric`)
- 금액 입력은 숫자 이외 문자를 제거한다.
- 선행 0은 제거한다.
- 화면에는 천 단위 콤마를 붙여 표시한다.
- 빈 금액은 저장 시 0으로 처리한다.

계산:

- `remainingAmount = estimatedAmount - paidAmount`
- 남은 금액이 음수면 `예산 초과 금액` 카드와 경고 문구 표시
- 전체 요약의 남은 결제금액은 음수로 내려가지 않고 0으로 보정한다.

저장 데이터:

- `estimatedAmount`, `contractAmount`, `paidAmount`: number
- `payer`: `groom`, `bride`, `shared`
- `contractPaymentDate`, `balancePaymentDate`: 선택 시 해당 날짜 00:00 기준 Timestamp
- `paymentDate`: 알림 worker와 기존 홈 화면 호환을 위해 잔금일과 동일하게 저장
- `relatedScheduleId`: 선택 없으면 null
- `createdBy`, `updatedBy`, `createdAt`, `updatedAt` 관리

구현상 검증 주의:

- paidAmount가 estimatedAmount를 초과해도 저장은 가능하고 경고만 표시한다.
- 계약금이 현재까지 결제 금액보다 큰 경우를 막지 않는다.
- 계약금일이 잔금일보다 늦은 경우를 막지 않는다.
- 세부 카테고리는 자유 입력이며 trim 검증은 없다.
- 관련 일정 select는 향후 365일 내 `type == "wedding"` 일정만 표시한다.

### 8.6 예산 저장/수정/삭제 플로우

추가:

1. 폼 입력
2. `예산 항목 저장`
3. `addBudgetItem(coupleId, uid, input)`
4. 문서 생성 후 `budgetId` 갱신
5. 폼 닫힘
6. 토스트: `예산 항목을 추가했어요.`

수정:

1. 수정 폼 입력
2. `수정 저장`
3. `updateBudgetItem(coupleId, budgetId, uid, input)`
4. `updatedBy`, `updatedAt` 갱신
5. 폼 닫힘, `editing=null`
6. 토스트: `예산 항목을 수정했어요.`

삭제:

1. 삭제 버튼 클릭
2. ConfirmDialog 표시
3. 제목: `예산 항목을 삭제할까요?`
4. 설명: `삭제한 예산 항목은 바로 복구할 수 없어요.`
5. 확인 시 `deleteBudgetItem`
6. 토스트: `예산 항목을 삭제했어요.`

오류:

- 저장 실패: `예산 저장에 실패했어요.`
- 삭제 실패: `예산 항목 삭제에 실패했어요.`
- Firestore 권한 실패도 사용자용 오류 메시지로 매핑되어 토스트에 표시된다.

## 9. 설정 `/settings`

### 9.1 내 정보

노출:

- 이름: `profile.displayName`
- 이메일: `profile.email`
- 현재 모드: 커플 모드 또는 예비부부 모드

상태:

- 프로필은 AuthGate에서 보장되므로 화면 내 별도 로딩은 없다.

### 9.2 사용 모드 변경

화면:

- 커플 모드 버튼
- 예비부부 모드 버튼
- 현재 모드는 강조 표시
- 설명: 모드를 변경해도 기존 일정과 예산 데이터는 삭제되지 않음

전이:

1. 현재 모드와 다른 버튼 클릭
2. `pendingMode` 설정
3. ConfirmDialog 표시
4. 확인 시 `changeCoupleMode(coupleId, uid, pendingMode)`
5. 커플 문서 `mode`와 현재 사용자 프로필 `mode` 갱신
6. 성공 토스트: `사용 모드를 변경했어요.`
7. 하단 탭과 화면 기능이 새 모드에 맞게 변경

다이얼로그 문구:

- 커플 모드로 변경: `예산관리 탭과 결혼 준비 일정은 숨겨지지만 데이터는 보존돼요.`
- 예비부부 모드로 변경: `예산관리와 커플 일정·결혼 준비 일정 분리 기능을 사용할 수 있어요.`

데이터 정합성/주의:

- 기존 예산과 결혼 준비 일정은 삭제하지 않는다.
- 현재 구현은 모드 변경 시 현재 사용자 프로필만 갱신한다. 파트너 프로필의 `mode`는 즉시 갱신되지 않을 수 있으나, 화면은 커플 문서의 `mode`를 우선 사용한다.
- Firestore 예산 접근 권한은 커플 문서 `mode`를 기준으로 한다.

### 9.3 파트너 연결

연결 완료 상태:

- 파트너 프로필이 있으면 이름과 이메일 표시
- 파트너 프로필 로딩 중이면 `파트너 정보를 불러오는 중이에요.`
- `커플 연결 해제` 버튼 표시

미연결 상태:

- `아직 파트너가 연결되지 않았어요.`
- 현재 초대코드 표시
- 복사 버튼
- `/invite`로 가는 `초대코드 입력하기` 링크

초대코드 복사:

- 성공: `초대코드를 복사했어요.`
- 실패: `초대코드 복사에 실패했어요.`

### 9.4 커플 연결 해제

진입:

- 연결 완료 상태에서 `커플 연결 해제` 클릭

다이얼로그:

- 제목: `커플 연결을 해제할까요?`
- 설명: `현재 공유 일정과 예산은 상대방 공간에 보존되며, 내 계정에서는 더 이상 볼 수 없어요.`
- 확인 버튼: `연결 해제`

처리:

1. 기존 커플 문서에서 파트너만 `memberIds`에 남긴다.
2. 기존 커플의 초대코드를 새 코드로 교체한다.
3. 기존 초대코드 인덱스 삭제, 새 초대코드 인덱스 생성
4. 현재 사용자를 위한 새 커플 문서 생성
5. 새 커플 문서에는 기존 모드를 유지하고 `memberIds=[uid]`
6. 현재 사용자 프로필의 `coupleId`, `mode`를 새 공간으로 갱신
7. 기존 커플 공간에 저장된 현재 사용자의 FCM 토큰 삭제
8. 성공 토스트: `커플 연결을 해제했어요.`

데이터 정합성:

- 기존 공유 일정과 예산은 기존 커플 공간에 남아 파트너가 계속 보유한다.
- 연결 해제한 사용자는 새 빈 커플 공간으로 이동하므로 기존 공유 데이터를 볼 수 없다.
- 파트너가 없는 상태에서 연결 해제를 시도하면 `연결된 파트너가 없어요.`

### 9.5 비밀번호 변경

진입:

- `비밀번호 변경` 버튼 클릭
- 전체 화면 다이얼로그 표시

필드:

- 현재 비밀번호: 필수, 최소 6자
- 새 비밀번호: 필수, 최소 6자
- 새 비밀번호 확인: 필수, 최소 6자

검증:

- 새 비밀번호와 확인값이 다르면 즉시 오류: `새 비밀번호가 서로 일치하지 않아요.`
- 현재 비밀번호가 다르면 `현재 비밀번호가 일치하지 않아요.`
- Firebase가 최근 로그인 필요를 반환하면 재로그인 안내 메시지 표시

처리:

1. 현재 비밀번호로 재인증
2. 새 비밀번호 업데이트
3. 성공 시 다이얼로그 닫힘
4. 토스트: `비밀번호를 변경했어요.`

닫기:

- 상단 X 또는 취소 버튼

### 9.6 알림 권한 요청

진입:

- `알림 권한 요청` 클릭

Android 앱 WebView:

1. 네이티브 브리지 존재 여부 확인
2. `requestPushToken` 메시지 전송
3. 최대 15초 응답 대기
4. 권한 허용 및 토큰 수신 시 `fcmTokens/{token}` 저장
5. 이전 토큰이 있고 새 토큰과 다르면 이전 토큰 삭제

일반 웹 브라우저:

1. `Notification.requestPermission()`
2. 권한이 `granted`가 아니면 오류
3. Firebase Messaging 지원 여부 확인
4. VAPID key로 FCM 토큰 발급
5. `fcmTokens/{token}` 저장

성공:

- 토스트: `알림 권한과 FCM 토큰을 저장했어요.`

오류:

- 권한 거부: `알림 권한이 허용되지 않았어요.`
- 브라우저 미지원: `현재 브라우저는 웹 푸시를 지원하지 않아요.`
- 토큰 미발급: `FCM 토큰을 발급받지 못했어요.`
- Android 응답 타임아웃: `Android 앱에서 FCM 토큰 응답을 받지 못했어요.`

권한:

- 토큰 생성/수정은 커플 멤버이면서 `userId == request.auth.uid`인 경우만 허용된다.
- 토큰 삭제도 토큰 소유자만 가능하다.

### 9.7 로그아웃

처리:

1. 커플 ID가 있으면 현재 네이티브 FCM 토큰 삭제를 시도한다.
2. 토큰 삭제 실패는 무시하고 로그아웃을 계속한다.
3. Firebase Auth signOut
4. 보호 화면 접근 시 AuthGate가 `/login`으로 보낸다.

## 10. 푸시 알림과 백그라운드 플로우

### 10.1 일정 알림

트리거:

- 파트너가 일정을 생성하면 알림
- 파트너가 일정을 수정하면 알림
- `reminderEnabled`인 일정은 하루 전 오전 9시와 당일 오전 9시에 리마인드 알림

정합성:

- 알림 발송 대상은 같은 `coupleId`의 FCM 토큰이다.
- 중복 발송 방지는 `sentNotifications` 문서로 처리한다.
- 클라이언트는 `sentNotifications` 쓰기가 금지된다.

### 10.2 예산 결제 알림

트리거:

- 예비부부 모드 예산 항목의 계약금일/잔금일 하루 전 오전 9시 알림

정합성:

- 예산 알림은 커플 문서 `mode == "wedding"`인 경우만 의미가 있다.
- `paymentDate`는 잔금일 호환 필드로 함께 유지된다.

## 11. Firestore 권한/데이터 정합성 체크포인트

공통:

- 비로그인 사용자는 모든 데이터 접근 불가
- `users/{uid}` 쓰기는 본인만 가능
- 사용자 문서 읽기는 본인 또는 같은 커플의 멤버만 가능
- 커플 멤버는 최대 2명

초대코드:

- 로그인 사용자는 특정 초대코드 문서 get 가능
- 초대코드 list는 금지
- 초대코드 update는 금지
- 초대코드 delete는 해당 커플 멤버만 가능

커플:

- 커플 문서 읽기/list는 멤버만 가능
- 생성 시 생성자가 본인이고 본인이 멤버에 포함되어야 함
- 모드는 `couple` 또는 `wedding`
- 업데이트는 멤버 또는 단독 커플에 새 멤버로 합류하는 제한 케이스만 허용

일정:

- 커플 멤버만 CRUD 가능
- 규칙상 일정 필드 스키마 세부 검증은 없다. 클라이언트 입력값 신뢰도가 중요하다.

예산:

- 커플 멤버이고 커플 문서가 `wedding` 모드일 때만 CRUD 가능
- 커플 모드 전환 즉시 Firestore 규칙 기준 예산 접근은 차단된다.

푸시 토큰:

- 커플 멤버만 읽을 수 있다.
- 생성/수정/삭제는 본인 `userId` 토큰만 가능하다.

## 12. 오류/빈/로딩 상태 요약

공통 로딩:

- AuthGate: `불러오는 중이에요`
- 홈 일정: `다가오는 일정을 불러오는 중이에요`
- 캘린더: `월간 일정을 불러오는 중이에요`
- 예산: `예산 항목을 불러오는 중이에요`
- 버튼 저장 중: 로그인/회원가입 버튼 비활성, 일정 저장 버튼 비활성, 예산 저장 버튼 비활성, 비밀번호/재설정 버튼 비활성

공통 빈 상태:

- 홈 일정 없음: `아직 등록된 일정이 없어요`
- 캘린더 선택일 일정 없음: `두 분의 첫 일정을 추가해보세요`
- 홈 예정 결제일 없음: `예정된 결제일이 없어요`
- 예산 항목 없음: `결혼 준비, 하나씩 정리해볼까요?`
- 커플 모드 예산 접근: `예산관리는 예비부부 모드에서만 사용할 수 있어요`

공통 오류:

- 인증/프로필 오류: 전용 오류 화면, 다시 시도, 로그아웃
- 저장/삭제 오류: 토스트
- Firebase Auth 오류: 사용자용 한국어 메시지로 매핑

## 13. QA용 주요 시나리오

1. 신규 회원가입 후 온보딩에서 커플 모드 선택, 초대코드 생성 확인, 홈 이동 전 파트너 미연결 문구 확인
2. 신규 회원가입 후 예비부부 모드 선택, 하단 예산관리 탭 노출 확인
3. 초대코드 복사, 재생성 후 기존 코드로 연결 실패와 새 코드 연결 성공 확인
4. 두 번째 계정이 초대코드로 합류하면 양쪽에서 파트너 이름/이메일 표시 확인
5. 커플 모드 캘린더에서 일정 추가, 수정, 삭제 확인
6. 예비부부 모드 캘린더에서 커플 일정과 결혼 준비 일정 필터 분리 확인
7. 예산 항목 추가 시 금액 콤마, 예산 초과 경고, 계약금일/잔금일 표시, 홈 결제일 노출 확인
8. 예산 항목 필터와 결제일/최근 추가 정렬 확인
9. 커플 모드로 변경 시 예산 탭 미노출, `/budget` 직접 접근 시 홈 이동 확인
10. 다시 예비부부 모드로 변경 시 기존 예산 데이터가 남아 있는지 확인
11. 비밀번호 변경에서 불일치, 현재 비밀번호 오류, 성공 케이스 확인
12. 알림 권한 거부/허용, FCM 토큰 저장 권한 확인
13. 커플 연결 해제 후 실행자에게 새 커플 공간과 새 초대코드가 생기고 기존 공유 데이터가 보이지 않는지 확인
