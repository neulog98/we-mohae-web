# UX/UI Review: Enterprise SaaS 관점

## 리뷰 범위

- 대상 앱: `우리뭐해` Next.js/PWA
- 확인 파일: `src/app/*`, `src/components/*`, `src/app/globals.css`, `tailwind.config.ts`, `README.md`
- 주요 화면: 로그인, 온보딩, 초대 연결, 홈, 캘린더, 예산관리, 설정
- 관점: 엔터프라이즈급 SaaS 운영 도구 UX/UI 기준

## 총평

현재 앱은 커플/예비부부가 모바일에서 빠르게 일정과 예산을 기록하는 개인 생산성 앱으로는 구조가 명확하다. 하단 탭, 카드형 요약, CRUD 폼, 토스트, 확인 다이얼로그 등 필수 패턴이 갖춰져 있고, 모바일 PWA 기준의 터치 타깃도 대체로 확보되어 있다.

다만 엔터프라이즈 SaaS 솔루션 기준으로 보면 정보 구조, 데이터 밀도, 반복 업무 효율, 상태 가시성, 권한/감사/보안 신뢰 표현이 부족하다. 현재 경험은 "간단한 기록 앱"에 가깝고, 여러 사용자가 운영 데이터를 지속적으로 관리하는 "업무용 콘솔"로 확장되기에는 탐색성, 테이블/필터/배치 작업, 오류 복구, 변경 이력, 빈/로딩/권한 상태의 체계화가 필요하다.

## IA / 내비게이션 / 정보 밀도 / 반복 업무 효율

### 강점

- `AppShell`은 홈, 캘린더, 예산관리, 설정의 1차 탭 구조를 명확하게 제공한다.
- 예비부부 모드에서만 예산관리 탭을 노출하는 조건부 IA는 사용자 맥락에 맞다.
- 홈 화면은 오늘 날짜, 파트너 연결 상태, 다가오는 일정, 예산 요약, 결제 예정 항목을 한 번에 보여주며 개인용 대시보드 역할을 한다.
- 캘린더 화면은 월간 뷰와 선택 일자 리스트를 결합해 일정 조회와 추가를 같은 화면에서 처리한다.
- 예산관리 화면은 요약, 카테고리 필터, 정렬, 항목 리스트, 등록 폼의 기본 업무 흐름이 연결되어 있다.

### 한계

- 전체 IA가 모바일 하단 탭 4개에 고정되어 있어 엔터프라이즈 SaaS에서 요구되는 하위 정보 구조를 수용하기 어렵다. 예: 감사 로그, 알림 설정, 권한, 데이터 내보내기, 업체/계약 관리, 리포트, 결제 캘린더 등.
- 홈 대시보드는 요약 카드가 있지만 운영자가 "오늘 처리해야 할 일", "지연/초과/위험 항목", "최근 변경", "담당자별 액션"을 빠르게 판단하기 어렵다.
- 캘린더의 일정 추가 폼이 항상 본문 하단에 노출되어 리스트 조회와 작성 업무가 한 화면에서 섞인다. 일정이 많은 사용자의 반복 조회 효율이 낮아질 수 있다.
- 예산 항목은 카드 리스트 중심이라 항목 수가 늘어나면 비교, 정렬, 스캔, 대량 수정, 상태 확인이 어렵다. SaaS 운영 도구라면 테이블 또는 밀도 높은 리스트 모드가 필요하다.
- 검색이 없다. 일정명, 예산 항목명, 카테고리, 메모, 관련 일정 기준 검색이 없으면 데이터가 쌓일수록 회수성이 급격히 떨어진다.
- 필터가 제한적이다. 예산은 카테고리와 정렬만 있고, 결제자, 결제 상태, 초과 여부, 결제일 범위, 관련 일정 유무 같은 운영 필터가 없다.
- 반복 입력을 줄이는 기능이 부족하다. 일정/예산 복제, 최근 입력값 재사용, 템플릿, 빠른 추가, 일괄 상태 변경, CSV 내보내기/가져오기 같은 SaaS형 생산성 기능이 없다.

## 디자인 시스템 일관성 / 컴포넌트 재사용성 / 상태 표현

### 강점

- Tailwind 확장 컬러(`rosewood`, `coral`, `mint`, `ink`, `cloud`)와 `shadow-soft`가 정의되어 있어 기본 시각 언어는 존재한다.
- 카드, 버튼, 입력, 세그먼트 컨트롤, 토스트, 확인 다이얼로그가 반복 사용된다.
- 삭제, 수정, 복사, 알림, 로그아웃 등 주요 액션에 `lucide-react` 아이콘을 사용해 터치 UI의 인지성을 보완한다.
- `StateView`로 로딩/빈/오류 상태의 최소 공통 컴포넌트를 제공한다.
- `BudgetForm`은 섹션 구조, 금액 입력 포맷, 초과 예산 경고, 고정 하단 액션 바를 갖춰 다른 폼보다 완성도가 높다.

### 한계

- 디자인 토큰이 색상 5개와 그림자 1개 수준에 머문다. 엔터프라이즈 UI에 필요한 spacing, radius, typography scale, border, focus ring, semantic color, density variant, elevation 기준이 없다.
- 같은 역할의 입력 필드 스타일이 컴포넌트마다 다르다. `BudgetForm`은 `inputClassName`과 focus ring이 있으나 `ScheduleForm`, `LoginPage`, `InvitePage`는 별도 클래스 조합을 사용한다.
- 버튼 변형이 체계화되어 있지 않다. primary, secondary, destructive, ghost, icon-only, disabled, loading 상태가 공통 컴포넌트로 정리되어 있지 않다.
- 카드 radius가 `rounded-md`, `rounded-lg`로 혼재한다. SaaS 도구에서는 컴포넌트별 radius 규칙을 고정하는 편이 전문성과 일관성을 높인다.
- 상태 표현이 텍스트와 색상에 많이 의존한다. 예산 초과는 잘 표현되지만, 일정 알림 활성화, 결제 예정/완료/미정, 연결 상태, 저장 중, 권한 제한, 동기화 실패 같은 상태는 배지/아이콘/설명 체계가 부족하다.
- 토스트는 시각적으로만 노출되고 `aria-live`가 없다. 성공/오류 메시지가 운영상 중요한 피드백이라면 접근성과 로그성 모두 강화해야 한다.
- `ConfirmDialog`는 공통화되어 있으나 focus trap, Escape 닫기, 배경 스크롤 잠금, 초기 포커스 지정이 보이지 않는다.

## 접근성 / 반응형 / 빈·로딩·오류 상태

### 강점

- 대부분의 아이콘 버튼에 `aria-label`이 있어 스크린 리더 사용자에게 기본 액션 의미가 전달된다.
- 주요 버튼은 `min-h-11`, `min-w-11`을 사용하는 경우가 많아 모바일 터치 타깃이 양호하다.
- `html lang="ko"`가 설정되어 있고, 입력 label도 대체로 명시되어 있다.
- `AuthGate`, `StateView`, 토스트, 다이얼로그 등 기본 상태 흐름은 구현되어 있다.
- `BudgetForm`의 전체 화면 다이얼로그와 하단 고정 액션은 모바일에서 긴 폼을 처리하기에 적절하다.

### 한계

- 앱 전체가 `max-w-md` 모바일 폭으로 고정되어 데스크톱/태블릿 반응형 사용성이 사실상 없다. 엔터프라이즈 SaaS는 데스크톱에서 대량 데이터 조회와 비교 작업이 핵심이므로 큰 화면 레이아웃이 필요하다.
- 데스크톱에서는 하단 탭보다 좌측 내비게이션, 상단 작업 바, 넓은 테이블/패널 조합이 적합하다.
- Focus style이 일관되지 않다. 일부 입력은 `outline-none`과 `focus:border-rosewood`만 있고, 버튼/링크의 명확한 키보드 포커스 표시가 부족하다.
- 색상 대비는 대체로 무난하나 `mint` 텍스트, `neutral-500`, 작은 배지 텍스트는 배경 조합에 따라 대비 검증이 필요하다.
- 폼 검증이 브라우저 기본 `required`, `minLength`에 의존한다. 업무용 도구라면 필드 단위 오류 메시지, 저장 실패 후 보존, 서버 오류 매핑, 중복/충돌 안내가 필요하다.
- 로딩 상태가 단순 텍스트 카드 중심이다. 리스트/요약/캘린더에는 skeleton, 부분 로딩, stale data 표시, 재시도 액션이 더 적합하다.
- 빈 상태는 친근하지만 운영 도구 관점의 다음 행동 안내가 약하다. 예: "필터를 초기화", "예산 항목 추가", "초대코드 복사", "샘플 템플릿 적용" 등 즉시 액션이 포함되면 전환율이 올라간다.
- 오류 상태는 일부 화면에만 있다. 캘린더/예산 데이터 구독 실패, FCM 권한 거부, 초대코드 만료/충돌, 네트워크 끊김 같은 상태가 화면 단위로 체계화되어 있지 않다.

## 신뢰감 / 보안감 / 운영 도구로서의 전문성

### 강점

- Firebase Auth, Firestore Security Rules, 멤버 기반 접근, 예산 기능의 모드 제한 등 기본 보안 모델이 README와 코드에 반영되어 있다.
- 삭제/연결 해제/모드 변경 같은 위험 작업에 확인 다이얼로그를 사용한다.
- 설정 화면에서 내 정보, 파트너 연결, 초대코드, 비밀번호 변경, 알림 권한, 로그아웃을 한 곳에 모아 계정 관리 흐름이 명확하다.
- 커플 연결 해제 시 데이터 보존 방식에 대한 설명이 있어 파괴적 액션의 불안을 줄인다.

### 한계

- UI에서 보안 신뢰 신호가 약하다. 초대코드 재생성, 알림 권한, 비밀번호 변경, 연결 해제는 있지만 최근 로그인, 세션 관리, 연결된 기기, 권한 범위, 데이터 접근 설명은 없다.
- 감사 가능성이 없다. 누가 일정을 만들고 수정했는지, 예산 항목의 변경 이력, 삭제 기록, 알림 발송 이력, 초대코드 재생성 이력을 확인할 수 없다.
- 삭제는 실제 삭제 중심으로 보이며, UI에서 복구 가능성이나 보존 정책이 명확하지 않다. 엔터프라이즈 환경에서는 soft delete, undo, 보존 기간, 감사 로그가 중요하다.
- 초대코드는 큰 글자와 복사/재생성 액션이 있지만 만료 여부, 사용 가능 횟수, 마지막 재생성 시각, 공유 주의 안내가 부족하다.
- 전체 시각 톤은 부드럽고 개인적이다. 엔터프라이즈 SaaS의 전문성 관점에서는 더 절제된 대비, 밀도 높은 데이터 패널, 명확한 상태 배지, 관리 콘솔형 네비게이션이 필요하다.
- 홈 카피가 친근한 대화체 중심이다. B2B 또는 운영 도구로 포지셔닝하려면 핵심 지표와 업무 상태를 더 직접적으로 표현하는 톤이 필요하다.

## 우선순위 개선 권고안

### P0: 운영 효율과 신뢰에 직접 영향을 주는 개선

1. 데스크톱/태블릿 레이아웃 추가
   - `max-w-md` 단일 모바일 셸을 유지하되, `md` 이상에서는 좌측 내비게이션 + 상단 바 + 2컬럼/3컬럼 콘텐츠 영역으로 확장한다.
   - 캘린더는 월간 캘린더와 선택 일자 리스트/폼을 분리 패널로 배치한다.
   - 예산관리는 요약 KPI, 필터 바, 테이블/리스트, 상세 패널 구조로 재설계한다.

2. 예산관리의 데이터 밀도 강화
   - 카드 리스트 외에 테이블형 뷰를 제공한다.
   - 컬럼 후보: 항목명, 카테고리, 결제자, 예상 금액, 결제 금액, 남은 금액, 계약금일, 잔금일, 초과 여부, 관련 일정.
   - 결제일 범위, 결제자, 초과 여부, 관련 일정 유무, 미정 날짜 필터를 추가한다.

3. 상태 체계 정비
   - 공통 `Badge`, `Button`, `Input`, `Select`, `Dialog`, `Toast`, `EmptyState`, `ErrorState` 컴포넌트를 정의한다.
   - 상태 색상은 semantic token으로 분리한다: success, warning, danger, info, neutral.
   - 저장 중, 실패, 권한 없음, 동기화 실패, 오프라인, 데이터 없음 상태를 화면 단위로 명확히 제공한다.

4. 감사/보안 신뢰 UI 추가
   - 일정/예산 항목에 생성자, 마지막 수정자, 마지막 수정 시각을 표시한다.
   - 삭제는 undo 또는 soft delete 정책을 UI에 반영한다.
   - 설정에 초대코드 만료/재생성 이력, 연결된 파트너/기기, 알림 토큰 상태, 보안 안내를 추가한다.

### P1: 반복 업무 생산성을 높이는 개선

1. 검색과 고급 필터 추가
   - 전체 검색: 일정명, 설명, 예산 항목명, 메모.
   - 캘린더 필터: 일정 유형, 카테고리, 알림 여부, 기간.
   - 예산 필터: 카테고리, 결제자, 결제일, 금액 범위, 초과 상태.

2. 빠른 작업 패턴 추가
   - 일정/예산 복제, 최근 입력값 재사용, 템플릿 저장.
   - 예산 항목에서 바로 결제 금액 업데이트.
   - 필터 초기화, 정렬 토글, 대량 선택 후 삭제/상태 변경.

3. 대시보드 재구성
   - "다가오는 일정"보다 "오늘/이번 주 할 일", "결제 임박", "예산 초과", "미정 항목", "최근 변경"을 우선한다.
   - 예비부부 모드에서는 결혼 준비 운영 보드로, 커플 모드에서는 일정 중심 보드로 정보 위계를 분리한다.

4. 폼 검증과 복구 강화
   - 종료일이 시작일보다 빠른 경우, 결제 금액이 음수/비정상인 경우, 필수 날짜 누락 등 도메인 검증을 추가한다.
   - 저장 실패 시 입력값을 유지하고 필드별 오류를 표시한다.
   - 제출 버튼은 저장 중 중복 클릭을 방지하고, 실패 시 재시도 액션을 제공한다.

### P2: 완성도와 확장성을 높이는 개선

1. 디자인 토큰 확장
   - typography, spacing, radius, shadow, border, focus ring, semantic color token을 정의한다.
   - 카드 radius, 버튼 높이, 폼 필드 높이, 배지 스타일을 컴포넌트별로 고정한다.

2. 접근성 보강
   - 모든 인터랙션 요소에 명확한 focus-visible 스타일을 적용한다.
   - 토스트에 `aria-live`를 적용한다.
   - 다이얼로그 focus trap, Escape 닫기, 초기 포커스, 배경 스크롤 잠금을 구현한다.
   - 색상 대비를 WCAG AA 기준으로 검증하고 작은 텍스트 배지의 대비를 높인다.

3. 빈 상태와 도움말 정교화
   - 빈 리스트에는 설명 + 바로 실행 가능한 CTA를 제공한다.
   - 초대, 알림 권한, 결제일 설정처럼 실패 가능성이 높은 흐름에는 짧은 보조 설명과 문제 해결 액션을 둔다.

4. 전문적인 운영 톤 적용
   - 친근한 문구는 유지하되, 운영 판단이 필요한 곳은 구체적인 상태명과 숫자를 우선한다.
   - 예: "다가오는 결제일이 있어요"보다 "7일 내 결제 예정 3건", "예산 초과 2건"처럼 의사결정형 문구를 사용한다.

## 화면별 핵심 제안

### 홈

- 현재: 날짜, 파트너 상태, 일정 미리보기, 예산 요약 중심.
- 제안: KPI/작업 큐 대시보드로 재구성한다.
- 추가 지표: 이번 주 일정 수, 오늘 일정, 결제 임박, 예산 초과, 미정 결제일, 최근 수정.

### 캘린더

- 현재: 월간 캘린더, 선택 일자 리스트, 하단 일정 폼.
- 제안: 조회와 작성 영역을 분리한다. 데스크톱은 캘린더/리스트/상세 패널, 모바일은 FAB 또는 하단 시트 기반 작성 흐름이 적합하다.
- 추가 기능: 일정 검색, 카테고리 필터, 알림 활성 상태 배지, 반복 일정, 일정 복제.

### 예산관리

- 현재: 요약 카드, 카테고리 필터, 정렬, 카드 리스트, 전체 화면 폼.
- 제안: 엔터프라이즈 SaaS에 가장 가까운 화면으로 발전시킬 수 있다. 테이블 뷰, 고급 필터, 결제 상태 배지, 초과 경고, 상세 패널을 우선 도입한다.
- 추가 기능: 결제 예정 캘린더, 금액 변경 이력, CSV 내보내기, 결제자별 분담 리포트.

### 설정

- 현재: 내 정보, 모드 변경, 파트너 연결, 비밀번호, 알림, 로그아웃.
- 제안: 계정/보안/연결/알림 섹션을 더 명확히 분리한다.
- 추가 기능: 최근 보안 이벤트, 초대코드 만료/재생성 정책, 연결된 알림 토큰 상태, 데이터 삭제/내보내기 정책.

## 결론

현재 UI는 모바일 개인 앱으로는 간결하고 사용 진입 장벽이 낮다. 그러나 엔터프라이즈 SaaS 관점에서는 큰 화면 정보 밀도, 데이터 회수성, 반복 작업 효율, 상태/권한/감사 표현이 부족하다. 우선 데스크톱 레이아웃, 예산 테이블, 검색/필터, 공통 디자인 시스템, 감사/보안 신뢰 UI를 보강하면 운영 도구로서의 전문성과 확장성이 크게 개선된다.
